# Lee's Process — Working with AI Agents

> **Human-AI collaboration protocol for dashForge**

---

## Session Lifecycle

### 1. Start of Session

**Human does:**

- Review `WHERE_AM_I.md` for product-level state
- Identify the next task from `sprint-plan.md`
- Open editor/terminal and start AI agent

**AI does:**

- Read `AGENTS.md` first
- Read `context.md`, `result-review.md`, `sprint-plan.md`, and `WHERE_AM_I.md`
- Re-read `product-definition.md` and `architecture.md` when implementation or scope choices are involved
- Read relevant code and documentation before acting
- Ask clarifying questions if needed

### 2. During Session

**AI execution pattern:**

1. Understand the task and constraints
2. Plan approach and explain it briefly
3. Implement incrementally
4. Test as you go
5. Update documentation and project memory

**Communication:**

- Be specific about file paths and changes
- Flag blockers immediately
- Ask for human input on decisions with non-obvious consequences

### 3. End of Session

**AI must update:**

- [ ] `context.md` — current work stream, decisions, and next actions
- [ ] `WHERE_AM_I.md` — what was done and what is next
- [ ] `sprint-plan.md` — mark tasks complete
- [ ] `result-review.md` — log results if the work was meaningful

**Format for updates:**

```markdown
## 2026-03-31 — Brief description

What was done:
- Change 1
- Change 2

Next steps:
- Next task

Blockers:
- Any issues?
```

## Communication Style

### Human to AI

- **Task format**: "Do X. Constraints: Y. Output to Z."
- **Context**: Reference relevant files and decisions
- **Priority**: Mark urgent tasks clearly

### AI to Human

- **Status updates**: Concise and specific
- **Blockers**: Immediate, with context
- **Results**: File paths and commands to verify

---

## Definition of Done

A task is done when:

1. Code works, if code was changed
2. Documentation is updated
3. `WHERE_AM_I.md` reflects new state
4. `context.md` and `sprint-plan.md` reflect the new state
5. A human can pick up where the AI left off
