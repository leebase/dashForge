# Idle Warehouse Waste Slice Contract

## Overview

DashForge operates as an internal Anblicks consulting accelerator engineered to deliver rapid, credible, and interactive dashboard experiences for enterprise client discovery workshops. Under the project's decoupled architectural model, sibling project `dataForge` is responsible for deterministic mock data generation, statistical modeling, and synthetic data quality assurance, while DashForge owns scenario definitions, `DashboardSpec` schemas, `DataAdapter` runtime interfaces, and standalone presentation deliverables.

The `idle-warehouse-waste` vertical slice establishes the end-to-end realization of the Snowflake Cost Management accelerator in DashForge. This slice demonstrates how a complex, relational cloud infrastructure cost story—specifically unmonitored and idle Snowflake compute warehouses consuming financial credits without active workload—is ingested from dataForge as a read-only, provenance-labeled snapshot, bound through canonical `DashboardSpec` contracts and `DataAdapter` runtime seams, and presented to executive buyers (CFOs, CIOs, and FinOps practice leaders) with prioritized, owner-validated recommendations and explicit synthetic disclosures. By proving these seams in a fully offline, zero-dependency standalone deliverable, DashForge enables Anblicks consultants to conduct authoritative pre-sales and architectural discovery workshops without requiring live customer credentials or cloud network connectivity.

## Problem

Enterprise analytics and consulting delivery teams face persistent credibility and governance barriers when engaging executive buyers on cloud data warehouse cost optimization. Abstract slide decks, generic wireframes, and simplistic mockups fail to convey the analytical depth necessary to establish consulting authority. Conversely, connecting to a client's live Snowflake production environment during initial pre-sales conversations or early discovery workshops is almost always blocked by enterprise infosec, data privacy, and procurement constraints.

Consultants therefore require a realistic, interactive demonstration environment that reflects recognizable enterprise operational friction: warehouses running 24/7 with zero active queries, unassigned ownership, missing resource monitors, and excessive auto-suspend timeouts. To deliver commercial impact, this experience must not be a hardcoded toy or disconnected visual mockup. It must consume deterministic dataForge exports as a provenance-labeled snapshot conforming to canonical contracts, prove that Snowflake cost data flows cleanly through DashForge's standard `DashboardSpec` and `DataAdapter` runtime seams, and present actionable, prioritized recommendations derived directly from the `recommendation_queue` dataset with explicit governance guardrails. Furthermore, this vertical slice must maintain strict backwards compatibility, ensuring that existing core features, scenario catalogs, and industry packs (`healthcare`, `financial`, `saas`) remain completely intact without regressions.

## Constraints

The implementation, execution, and verification of the `idle-warehouse-waste` vertical slice are subject to the following technical and governance constraints:

1. **Canon Alignment**: All designs, schemas, CLI interfaces, and presentation contracts must strictly conform to `product-definition.md`, `architecture.md`, `AGENTS.md`, `README.md`, and preceding slice contracts (`docs/package-dataforge-snapshot-contract.md` and `docs/snowflake-cost-pack-contract.md`).
2. **Read-Only dataForge Boundary**: Sibling repository `dataForge` is strictly read-only. No files within `dataForge/` may be added, edited, or removed during development, testing, or execution.
3. **Canonical Snapshot Conformance**: The slice must consume scenario exports conforming strictly to the canonical `SQLiteSnapshot` TypeScript contract defined in `frontend/src/core/data/sqliteSnapshot.ts` and generated via `src/dashForge/package_snapshot.py`. No secondary or bespoke snapshot formats may be introduced.
4. **Provenance and Synthetic Disclosure Integrity**: Exported snapshot artifacts and presentation views must carry complete provenance tracing (`packId: "snowflakeCost"`, `scenarioId: "idle-warehouse-waste"`, `seed: 9101`, `dataForgeStoryContractPath`, generator version, ISO-8601 generation timestamp, `synthetic: true`, and disclosure text `"Synthetic demo data"`). Synthetic disclosures must remain prominent and unsuppressed across all UI views and exported artifacts.
5. **Runtime Seam Preservation**: The vertical slice must prove and preserve the canonical `DashboardSpec` -> `DataAdapter` (`createDashboardDataAdapter`, `StaticDataAdapter`, `SyntheticDataArtifactAdapter`, or `SQLiteDataAdapter`) -> `DashboardRenderer` seam. Supplemental presentational components must read from the same registered scenario snapshot without bypassing the core architecture or introducing a disparate rendering engine.
6. **Prioritized Recommendation Governance**: Recommendations presented to users must be derived directly from the `recommendation_queue` dataset and preserve all governance columns (`recommendation_id`, `executive_severity`, `suggested_owner`, `recommended_action`, `evidence_detail`, and `guardrail`). Recommendations must be explicitly framed as directional until validated with designated warehouse owners, with no auto-applied or destructive actions permitted.
7. **Fail-Closed CLI Behavior & Overwrite Guard**: The CLI command `env PYTHONPATH=src python3 -m dashForge.main generate` must fail closed with exit status 2 and clear diagnostic messages when required parameters are missing, invalid scenarios are supplied, or target output paths exist without the explicit `--force` flag.
8. **Zero External Runtime Dependencies**: All Python packaging, dispatching, and CLI interfaces must rely exclusively on Python standard library modules (`argparse`, `json`, `sqlite3`, `pathlib`, `sys`, `importlib`). No external runtime packages or live Snowflake credentials/SDKs may be introduced.
9. **Governed Write Scope**: Persistent artifact writes for this contract step are strictly limited to `docs/` and `journeys/`. Modifying out-of-scope paths causes immediate step failure under Agent-Orch governance.

## Validation

Verification of the `idle-warehouse-waste` slice follows a multi-tier deterministic validation methodology:

1. **Full Automated Test Suite Execution**: Execution of the complete pytest suite via `python3 -m pytest tests/ -q` with NO PYTHONPATH override (the orchestrator re-executes claims in a bounded environment whose own PYTHONPATH is what makes pytest importable, and an override hides it) to verify argument parsing, deterministic generation, snapshot schema conformance, and regression immunity across all packs (`healthcare`, `financial`, `saas`, `snowflakeCost`).
2. **Deterministic Output & Reproducibility**: Verification that repeated executions of the CLI with identical parameters (`--pack snowflakeCost --scenario idle-warehouse-waste --seed 9101`) produce bit-for-bit identical SQLite databases and JSON snapshots.
3. **Provenance & Synthetic Disclosure Verification**: Inspection of snapshot JSON metadata confirming the presence and validity of `packId`, `scenarioId`, `seed`, `dataForgeStoryContractPath`, generator version, generation timestamp, `synthetic: true`, and disclosure text `"Synthetic demo data"`.
4. **DataAdapter Seam and Query Proof**: Targeted test execution and runtime inspection confirming that scenario datasets (`executive_summary`, `warehouse_metering_history`, `query_history`, `metering_history`, `database_storage_usage_history`, `show_warehouses`, and `recommendation_queue`) are queried and aggregated via standard `DataAdapter` interfaces without secondary renderers.
5. **Recommendation Queue Safety & Schema Validation**: Automated inspection verifying that `recommendation_queue` retains `recommendation_id`, `executive_severity`, `suggested_owner`, `recommended_action`, `evidence_detail`, and `guardrail` columns, and that UI rendering enforces directional validation policies.
6. **User Journey Simulation Gate**: Execution of allowlisted user journey commands via Agent-Orch's `user_tester` gate, confirming that claimed exit codes and command behaviors reproduce identically from the workspace root.

- **Independent Reviewer Route (`slice_reviewer` / `gemini-3.1-pro`)**: Conducts read-only inspection of implementation diffs, test logs, contract adherence, and evidence integrity to issue an authoritative review verdict.
