# Idle Warehouse Waste Binding Slice Contract

## Overview

DashForge operates as an internal consulting delivery accelerator for Anblicks, designed to empower consultants and delivery leads to conduct high-impact, interactive enterprise discovery workshops without requiring live cloud credentials or network connectivity. Operating under DashForge's decoupled architectural model, sibling repository `dataForge` owns deterministic mock data generation, statistical distributions, and synthetic data quality assurance, while DashForge owns scenario packages, canonical `DashboardSpec` schemas, `DataAdapter` runtime interfaces, and standalone dashboard presentation deliverables.

The `idle-warehouse-waste-binding` vertical slice implements the core foundation for the Snowflake Cost Management accelerator within DashForge by binding the `idle-warehouse-waste` dataForge snapshot to a canonical DashForge `DashboardSpec`. This slice proves that complex, relational cloud infrastructure cost telemetry—specifically unmonitored and idle Snowflake compute warehouses consuming financial credits without active query workloads—can be ingested from dataForge as a read-only, provenance-labeled snapshot, mapped cleanly to standard `DashboardSpec` schemas and `DataAdapter` runtime seams, and presented to executive buyers (CFOs, CIOs, VPs of Data, and FinOps practice leaders) with prioritized, owner-validated recommendations and prominent synthetic disclosures.

Crucially, this slice establishes the end-to-end data and presentation binding using deterministic micro-steps to resolve previous worker timeouts while preserving the underlying generative contracts intact. By delivering a zero-dependency, browser-visible standalone experience, DashForge enables Anblicks consultants to demonstrate immediate commercial value in client workshops with bit-for-bit reproducibility.

## Problem

Enterprise consulting teams routinely face substantial credibility and operational hurdles during early-stage cloud financial operations (FinOps) and Snowflake cost optimization engagements. When meeting with executive decision-makers, consultants encounter a persistent structural dilemma:

1. **Production Credential Blockers**: Prospective enterprise clients cannot provide live credentials or direct access to their production Snowflake environments during pre-sales or initial discovery sessions due to strict enterprise security policies, compliance mandates, and data privacy regulations.
2. **The Credibility Deficit of Abstract Mockups**: Generic wireframes, static PowerPoint slides, or simplistic toy mockups fail to convey the analytical depth, relational nuance, and operational friction required to earn executive trust and demonstrate domain expertise.
3. **Throwaway Scaffolding and Timeout Bottlenecks**: Prior prototyping approaches frequently resulted in throwaway code that could not transition into production deliverables. Furthermore, previous complex monolithic implementation steps suffered from worker execution timeouts, requiring deterministic micro-steps and targeted verification to ensure reliable, repeatable execution across governed workflows.

Consultants require a reliable, standalone presentation environment reflecting realistic enterprise friction: compute warehouses running 24/7 with zero active queries, unassigned resource monitors, and excessive auto-suspend timeouts. To establish consulting credibility without throwaway work, the slice must consume deterministic dataForge exports as a canonical, provenance-labeled snapshot conforming to `SQLiteSnapshot` contracts, prove that Snowflake cost telemetry binds seamlessly through DashForge's standard `DashboardSpec` and `DataAdapter` seams, and present actionable, prioritized recommendations directly from the `recommendation_queue` dataset with explicit governance guardrails. The implementation must use bounded, deterministic micro-steps that avoid worker timeouts, maintain existing generative contracts, and preserve complete backwards compatibility across all existing industry packs (`healthcare`, `financial`, `saas`).

## Constraints

The architecture, implementation, and verification of the `idle-warehouse-waste-binding` slice are governed by the following mandatory technical and operational constraints:

1. **Canon Alignment and Generative Contract Preservation**: All schemas, data models, CLI interfaces, and presentation bindings must strictly conform to `product-definition.md`, `architecture.md`, `AGENTS.md`, and preceding slice contracts. The underlying generative contracts and schemas established across sibling project `dataForge` and `dashForge` must not be modified or bypassed.
2. **Read-Only Sibling Repository Boundary**: Sibling repository `dataForge/` is strictly read-only. No files within `dataForge/` may be created, edited, or removed during implementation or testing.
3. **Canonical Snapshot Conformance**: The slice must consume scenario exports conforming strictly to the canonical `SQLiteSnapshot` TypeScript contract in `frontend/src/core/data/sqliteSnapshot.ts` and packaged via `src/dashForge/package_snapshot.py`. No secondary, divergent, or bespoke snapshot formats may be introduced.
4. **Deterministic Micro-Steps to Prevent Worker Timeouts**: To eliminate worker execution timeouts experienced in previous attempts, implementation and verification must proceed through deterministic, bounded micro-steps. Targeted test executions and bounded commands must be prioritized over monolithic, unbounded invocations during step-level verification.
5. **Runtime Seam Preservation and Zero Primitive Fragmentation**: The slice must prove and preserve the canonical `DashboardSpec` -> `DataAdapter` (`createDashboardDataAdapter`, `StaticDataAdapter`, `SyntheticDataArtifactAdapter`, or `SQLiteDataAdapter`) -> `DashboardRenderer` seam. Presentational components and widgets must consume data exclusively through the `DataAdapter` interface across all seven scenario datasets without introducing secondary rendering pipelines or fragmented visual primitives.
6. **Prioritized Recommendation Queue Governance**: All recommendations presented to users must originate directly from the `recommendation_queue` dataset and preserve all six governance fields (`recommendation_id`, `executive_severity`, `suggested_owner`, `recommended_action`, `evidence_detail`, and `guardrail`). Recommendations must be explicitly framed as directional pending validation with designated warehouse owners, with no automated destructive operations permitted.
7. **Browser-Visible UI Contract & Synthetic Disclosures**: The standalone dashboard deliverable must be browser-visible at `/?scenario=idle-warehouse-waste` (served with the command from `tests/browser_smoke_manifest.json`: `python3 -m http.server 4173 --bind 127.0.0.1 --directory frontend/dist`). The root container must carry `data-scenario="idle-warehouse-waste"` and `data-readiness="controlled"`. The persistent disclosure element must carry `data-disclosure="synthetic-demo-data"` with the exact text `Synthetic demo data`. An interactive control with `data-action="open-recommendation-queue"` must open the recommendation queue with `data-status="recommendation-queue"`, and the follow-up export action with `data-action="same-day-executive-follow-up"` must be present.
8. **Fail-Closed CLI Overwrite Protection**: The CLI application entrypoint `env PYTHONPATH=src python3 -m dashForge.main generate` must fail closed with exit status 2 and clean diagnostic messages when required arguments are missing, unknown scenarios are requested, or output target paths already exist without the explicit `--force` flag.
9. **Zero External Runtime Dependencies**: All Python packaging, dispatching, and CLI interfaces must rely exclusively on Python standard library modules (`argparse`, `json`, `sqlite3`, `pathlib`, `sys`, `importlib`). No external runtime packages, live Snowflake credentials, or external SDKs may be introduced.
10. **Governed Write Scope**: Persistent file modifications for this step are strictly restricted to `docs/` and `journeys/`. Any write outside these paths fails the step under Agent-Orch governance rules.
