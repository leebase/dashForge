# Idle Warehouse Remediation Artifacts Slice Contract

## Overview

DashForge operates as an internal enterprise consulting delivery accelerator for Anblicks, designed to empower practice directors, client delivery leads, and data engineering consultants to conduct high-impact, credible executive discovery workshops. Rather than demonstrating analytics vision through abstract slide decks, conceptual wireframes, or empty business intelligence canvases, DashForge delivers fully functional, standalone client-side dashboard experiences that prove immediate consulting value completely offline and without requiring live cloud credentials or external network connectivity.

The `idle-warehouse-remediation-artifacts` vertical slice advances DashForge's Snowflake Cost Management optimization solution (`snowflakeCost:idle-warehouse-waste`) by bridging analytical discovery and concrete operational action. Built upon the foundational `idle-warehouse-waste` relational data layer and the browser-visible `idle-warehouse-dashboard` presentation tier, this slice focuses on delivering prioritized low-risk recommendations and same-day follow-up artifacts for the idle warehouse dashboard. This enables the buyer—typically a Chief Financial Officer (CFO), Chief Information Officer (CIO), VP of Data and Analytics, or enterprise FinOps practice leader—to immediately act on identified compute waste without leaving the application.

Importantly, this slice maintains absolute architectural stability across DashForge: existing dashboard functionality, URL scenario mounting at `/?scenario=idle-warehouse-waste`, controlled readiness state signaling, prominent synthetic demo data disclosures, browser smoke gate conformance, and backend CLI generation workflows must not change. By delivering actionable, low-risk remediation plans and exportable post-workshop deliverables, this slice enables consulting teams to transform early executive alignment into immediate engineering follow-through on the same day.

## Problem

Enterprise data leaders and FinOps executives are under severe pressure to identify and remediate cloud data warehouse spend inefficiencies, particularly Snowflake compute credit waste resulting from unmonitored idle warehouses, disabled auto-suspend settings (`auto_suspend = 0`), excessively prolonged suspension timeouts (such as 3600 seconds or greater), and unassigned resource monitors. While DashForge's existing Idle Warehouse Dashboard successfully visualizes the financial magnitude of this waste—surfacing a high-end monthly opportunity of 726 compute credits and identifying 2 unmonitored warehouses running continuously without active query workloads—consultants face a critical friction point during pre-sales and architectural discovery workshops.

Specifically, prospective buyers who see this waste are frequently paralyzed by operational risk and change inertia. Enterprise stakeholders are rightfully cautious about modifying cloud infrastructure settings, fearing that adjusting warehouse configurations might inadvertently disrupt business-critical analytics, batch ETL pipelines, or scheduled executive financial reporting. When presented with an undifferentiated list of recommendations, buyers cannot immediately distinguish zero-risk hygiene remediations from changes requiring extensive architectural refactoring. Furthermore, once an executive agrees in principle to address the waste, the consultant traditionally has to leave the presentation, manually extract metrics, write follow-up summary documents, and compose configuration scripts outside the tool. This post-meeting delay introduces communication lag, dissipates executive urgency, and creates misalignment between the consulting proposal and client engineering execution.

To eliminate this delivery bottleneck, the idle warehouse dashboard requires an integrated remediation capability that directly serves the buyer's need for immediate, safe, and actionable follow-through. The dashboard must clearly surface prioritized, low-risk recommendations—filtering and highlighting minimal-risk actions such as configuring aggressive auto-suspend and assigning resource monitors on ad-hoc warehouses like `FINANCE_REPORTING_WH`—while strictly preserving protective governance guardrails that frame all projected savings as directional pending designated owner validation. In addition, the application must provide same-day executive follow-up artifact generation directly from the interface, packaging key opportunity metrics, prioritized low-risk actions, suggested owners, and claim citations anchored to the verified work-package digest into decision-ready deliverables.

## Constraints

The implementation, verification, and operational execution of the `idle-warehouse-remediation-artifacts` slice are governed by the following strict constraints:

1. **Preservation of Existing Dashboard Functionality**: The slice must not alter existing dashboard navigation, URL scenario mounting (`/?scenario=idle-warehouse-waste`), DOM readiness states (`data-scenario="idle-warehouse-waste"`, `data-readiness="controlled"`), or core interactive behaviors such as the recommendation queue toggle (`data-action="open-recommendation-queue"`).
2. **Preservation of Backend Generation & CLI Flows**: Sibling project `dataForge` remains strictly read-only and untouched. All backend Python data generation algorithms, relational table structures, snapshot extractors, CLI generate commands (`env PYTHONPATH=src python3 -m dashForge.main generate`), and fail-closed overwrite protections requiring `--force` must remain fully intact and operational without regressions.
3. **Decoupled Architecture & Zero Live Dependencies**: The standalone presentation and follow-up artifact generation must run entirely in-browser without live Snowflake connections, external backend database services, cloud APIs, or third-party execution daemons. All data must resolve locally through `StaticDataAdapter` and canonical `DashboardSpec` contracts.
4. **Governed Low-Risk Prioritization**: Recommendations surfaced in the recommendation queue must preserve all six canonical governance fields (`recommendation_id`, `executive_severity`, `suggested_owner`, `recommended_action`, `evidence_detail`, and protective `guardrail`). Actions classified as low performance risk (such as auto-suspend configuration and resource monitor assignment) must be clearly prioritized, with `FINANCE_REPORTING_WH` (`IWW-001`, Priority `P0`) presented first.
5. **Mandatory Directional Validation Guardrails**: All projected credit savings and recommended configuration changes must be explicitly framed as directional until validated by designated warehouse owners. Automated or ungrounded destructive alterations to warehouse configurations are strictly forbidden.
6. **Persistent & Unsuppressed Synthetic Data Disclosures**: Every presentation view, printed view, and generated follow-up artifact must prominently feature the unsuppressed disclosure element `data-disclosure="synthetic-demo-data"` with the exact text `"Synthetic demo data"`, accompanied by upstream artifact digest citations and controlled quality state metadata, preventing synthetic workshop demonstrations from being misrepresented as production telemetry.
7. **Verbatim Workspace-Root Direct Argv Execution**: All commands declared in `command_allowlist` and recorded across user journeys must execute verbatim from the repository root using direct subprocess invocation (`shell=False`). Application CLI commands must use the exact form `env PYTHONPATH=src python3 -m dashForge.main`. The test suite command is exactly `python3 -m pytest tests/ -q` with NO `PYTHONPATH` override. Shell pipelines (`|`), boolean operators (`&&`, `||`, `;`), file redirection (`<`, `>`), and standalone shell tools (`jq`, `grep`, `cat`) are strictly prohibited as sole journey verification evidence.
8. **Browser Smoke Gate Conformance**: The compiled production build served from `frontend/dist` must conform exactly to `tests/browser_smoke_manifest.json` and `tests/browser_smoke_check.py`, preserving required contract markers: `"idle-warehouse-waste"`, `"synthetic-demo-data"`, `"open-recommendation-queue"`, and `"recommendation-queue"`.
9. **Governed Write Scope Enforcement**: Persisted file modifications for this step are strictly restricted to the `docs/` and `journeys/` directories. Modifying any path outside these boundaries results in immediate step failure under Agent-Orch governance.

7. **Automated Python Regression Suite**: Execution of `python3 -m pytest tests/ -q` with no `PYTHONPATH` override, confirming that backend packaging, deterministic snapshot generation, fail-closed CLI argument handling, and all industry packs (`healthcare`, `financial`, `saas`, `snowflakeCost`) pass cleanly with zero regressions.
